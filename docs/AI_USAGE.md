# AI使用与验证记录

## 辅助分工

候选人确定研究范围：机器人精细操作的执行与感知产业链。Codex负责方案细化、公开材料检索、程序实现和验证。产品运行时由Kimi负责候选关系提取及受限证据解释，代码负责确定性校验，用户负责确认来源与口径。

扶摇已使用用户本地配置的凭据完成真实接口验证，记录见fuyao-validation.json。iFinD已通过官方Skill及官网MCP代理进行工具清单验证与真实试查，见ifind-validation.json。未伪造接口结果；返回片段、财务口径与异常日期仍需核验，不自动升级为AI事实。Kimi密钥仅存本机忽略文件及托管秘密配置，所有交付记录不包含密钥。

## 关键验证问题

1. 有销量但没有单列收入：预期E3。
2. 集团收入加上灵巧手制造推进：预期E2，不能用集团收入证明灵巧手收入。
3. 3D视觉产品明确收入：预期E4，但不能全部归到机器人。
4. 证据问答：必须引用当前公司实际存在的证据ID，并解释口径限制。

实际结果、请求ID、token用量与响应耗时见JSON原始记录。文本为官方材料节选或表格文字化；页码和数值另行与PDF核对。

## 初轮失败与修正

首次真实验证中，Kimi把“批量生产工作持续推进”输出成销售级结论，代码因原文缺少销售信号返回422，结果没有写入研究库。提示词从extract-v1.0升级至extract-v1.1，明确“生产不是交付，无销售证据必须E2”。

首次问答遇到上游429，产品转换为503并提示限流/额度不足，未返回伪造研究结果。验证脚本增加请求间隔后重新执行。问答引用校验曾因“待验证”项没有事实引用而拦截；research-v1.1区分需要引用的事实/推断和允许无事实证据的待验证问题，并明确只能引用关系ID而非来源ID。真实回归已通过。初轮与中间拦截保留在`ai-validation-initial.json`和`ai-validation-v11-rejected.json`，不能只展示成功结果。

## 验证器的能力边界

校验来源URL白名单、输入长度、日期、字段结构、连续引用精确匹配、销售级信号、收入级金额和分项范围。它不能独立证明任意用户粘贴文本与远程年报相同，不能判断所有语义性财务误归属，也不能独立审计公司陈述。

基础快照另用下载的官方PDF核对关键页码与数值；新增材料须用户确认。验证状态不使用未经实际执行的“人工已审核”标签。模型限制、接口错误和失败结果明确记录。

## v2真实闭环与准确性

已执行柯力2026半年报官方PDF哈希核验、真实Kimi提取、签名检查、篡改拒绝、D1写入与去重、当前版本问答。extract-v1.2和research-v1.2结果见closed-loop-validation.json；该文件明确标记本地自动确认模拟，不伪称候选人已亲自确认。问答新增引用对应数值检查、原术语保留和集团/业务口径约束；语义仍须审阅，不宣称模型完全可靠。
